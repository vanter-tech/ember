- **WebSocket endpoint isolation gotcha (bugfixes, reports 193+194 — READ THIS before touching any `@EnableWebSocketMessageBroker` config):** Spring does NOT give a second `@Configuration implements WebSocketMessageBrokerConfigurer` its own isolated broker/channel, even with its own `@EnableWebSocketMessageBroker` — it collects EVERY such bean and applies ALL of their `registerStompEndpoints`/`configureClientInboundChannel`/`configureMessageBroker` callbacks onto ONE shared `clientInboundChannel`/`MessageBrokerRegistry`. EMB-PRINT's `PrintAgentWebSocketConfig` assumed otherwise (its own doc comment said so) and shipped TWO stacked regressions from that one wrong assumption: (1, report 193) `PrintAgentChannelInterceptor` ran on every `/ws` CONNECT too, rejecting every tenant JWT with `"Not a print-agent token"`; (2, report 194) `configureMessageBroker`'s `registry.enableSimpleBroker("/topic/print-agent")` call SILENTLY REPLACED (not merged with) `WebSocketConfig`'s `enableSimpleBroker("/topic", "/user")` — `MessageBrokerRegistry#enableSimpleBroker` overwrites its single registration on every call — so even after (1) was fixed, CONNECT/SUBSCRIBE/heartbeats worked but ZERO application broadcasts were ever delivered anywhere. Together these silently broke ALL realtime features (customer cart, KDS, waiter floor, inventory alerts) since report 180, undetected until a user manually reported it (no `claude-in-chrome` browser access in any session since). Fix (1): tag sessions at handshake time (`WebSocketSessionAttributes` + `PrintAgentHandshakeInterceptor` on `/ws/print-agent` only) so `PrintAgentChannelInterceptor`/`JwtChannelInterceptor` no-op for sessions that aren't theirs. Fix (2): `WebSocketConfig.configureMessageBroker` is now the ONE place registering broker prefixes — `enableSimpleBroker("/topic", "/user", "/topic/print-agent")` — and `PrintAgentWebSocketConfig` no longer overrides that method at all. **Any future second/third STOMP endpoint must follow both patterns: handshake-tag for interceptor scoping, and register ALL broker/destination prefixes from the ONE owning config — never assume a second config class adds to instead of replacing the shared registry.** `WebSocketEndpointIsolationTest` (`@SpringBootTest(RANDOM_PORT)` + real STOMP clients, including one that broadcasts via `SimpMessagingTemplate` and asserts delivery) is the only test shape that catches either bug class — a unit test of one interceptor in isolation cannot.
