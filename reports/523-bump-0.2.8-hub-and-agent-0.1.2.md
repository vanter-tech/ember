# Report 523 — Release bump: backend/Hub 0.2.8, print agent 0.1.2

## 1. Identification
- **Report number:** 523
- **Task ID:** RELEASE-0.2.8 (bump only)
- **Predecessor:** report 522 (HUB-PRINT-2), same PR

## 2. Objective
Version the release that ships HUB-LICENSE-HARDENING (r520), the agent "Servidor" field (r521) and receipt routing by caja (r522), so the installers do not overwrite previously published ones.

## 3. Modified Files
- `backend/pom.xml` — `0.2.7.1` → `0.2.8` (names `EmberHubSetup-<version>.exe` and the backend image tag)
- `printing-agent/pom.xml` — `0.1.1-SNAPSHOT` → `0.1.2` (names `EmberAgentSetup-<version>.exe`; `0.1.1` is the one already published)
- `reports/523-bump-0.2.8-hub-and-agent-0.1.2.md`

## 4. What Changed?
Only the two `<version>` lines. The Hub and agent installers derive their version from these poms (`Get-HubVersion` / `Get-AgentVersion`).

## 5. Why It Changed?
Two releases sharing a version overwrite each other in `gs://ember-downloads-prod` and block clean in-place updates (see `printing-agent/README.md`). It rides in the routing PR instead of its own to save a 17-minute CI round.

**Release order (license hardening):** tag `v0.2.8` → `deploy.sh 0.2.8` (cloud) **before** publishing `EmberHubSetup-0.2.8.exe` to customers; an old cloud sends no signature and the new Hub would reject every heartbeat.
