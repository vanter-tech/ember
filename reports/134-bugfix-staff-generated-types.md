# Report 134 — bugfix-staff-generated-types

**Predecessor Task:** EMB-STAFF-01..04 (Employee CRUD, reports 130–133)

## Objective
Swap the remaining hand-typed `api.ts` interfaces for their now-regenerated `backend-types.ts` schemas (user re-ran `pnpm run openapi`), continuing the same cleanup as report 128.

## Modified Files
- `frontend/src/lib/api.ts`
- `frontend/src/lib/backend-types.ts` (regenerated by the user; committed as-is)

## What Changed?
- `UpdateStaffProfileRequest`: the generated schema now includes `name`/`email` (added server-side in EMB-STAFF-03, report 132) — switched from the hand-typed interface back to `components['schemas']['UpdateStaffProfileRequest']`.
- `PublicBranding`: discovered while checking for other hand-typed interfaces still on this file — a generated `PublicBrandingResponse` schema already existed (unrelated to this session's work, predates it) but had never been swapped in. Switched to `components['schemas']['PublicBrandingResponse']`. Its fields are now optional (the generated schema, unlike the old hand-typed one, doesn't mark them required) — checked the one consumer (`TenantLanding.tsx`) and it already guards every field (`|| '#920703'` fallback, truthiness checks, or bare JSX interpolation, which renders `undefined` as nothing) so no call-site changes were needed.
- `PendingDigitalPayment`/`WaiterBillState` remain hand-typed — confirmed again these model WebSocket broadcast payloads, which the OpenAPI spec (REST-only) can never produce a schema for. `Page<T>` also stays hand-typed — it's a generic wrapper around Spring's `Page` JSON shape used across many endpoints, not tied to one schema.

## Why It Changed?
Direct continuation of the "swap hand-typed interfaces for generated ones once regenerated" pattern (report 128, then again here). Checking for *every* remaining hand-typed interface in the file, not just the one from the immediately preceding task, is what surfaced the older `PublicBranding` gap.
